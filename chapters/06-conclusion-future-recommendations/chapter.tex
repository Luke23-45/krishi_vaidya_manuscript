\chapter{CONCLUSION AND FUTURE RECOMMENDATIONS}

\ChapterSection{Conclusion}

This project set out to investigate whether an integrated system combining object detection,
vision-language interpretation, backend orchestration, and an offline-aware mobile application
could be designed, implemented, and evaluated for image-based crop-health diagnosis support in
the Nepalese agricultural context. The answer is conditional: the integrated system can be
designed and implemented, the individual components can be measured against objective criteria,
and the completed distributed runtime path can be verified---but the current VLM evidence does
not support a claim of reliable autonomous diagnostic output.

The YOLO detection subsystem provides the strongest quantitative evidence. With F1 0.73 and
mAP@50 0.76 at the best training epoch, the detector demonstrates viable plant-part localization
across eleven agricultural object classes. The INT8 quantized variant preserves 98 percent of
baseline mAP at 1.87$\times$ model compression, confirming that lightweight deployment is
feasible without substantial accuracy degradation. Per-class analysis reveals predictable
failure patterns---low recall on small or underrepresented classes such as rice panicle and
brassica leaf---that are consistent with the small-object detection literature rather than with
a fundamental architecture limitation.

The VLM subsystem contributes a complete fine-tuning pipeline: dataset curation from
PlantVillage sources, Qwen-format structured export, LoRA adapter training with 4-bit
quantization, inference gateway with JWT authentication, and automated evaluation. However, its
prediction results are the manuscript's most important analytical finding. The 67.7 percent
parse-error rate on the independent test set and the 13.1 percent overall classification accuracy
reveal that structured diagnostic output from a LoRA-adapted 3B-parameter VLM remains unreliable
under current training and decoding conditions. This result is valuable precisely because it
identifies concrete failure modes---parseability and label reliability---and connects them to
technical hypotheses about prompt-template mixture, output-format supervision, and constrained
decoding that future iterations can test.

The backend and mobile subsystems demonstrate that Krishi Vaidya was engineered as an
application, not constructed as a model-only experiment. The Express/Mongoose API validates
inputs, orchestrates VLM and advisory calls, enforces schema-validated responses, and provides
scan-domain test coverage. The React Native/Expo mobile application implements the complete
farmer-facing workflow: onboarding, scan capture, diagnosis display, crop-plot management,
notes, tasks, offline SQLite persistence, and synchronization infrastructure. The integration
path connects these components through documented contracts, and the offline-aware diagnosis
hook adapts behavior to network state---a practical necessity for Nepal's rural connectivity
conditions.

The project therefore demonstrates that the integration is architecturally sound and
implementation-complete, while the diagnostic core---the VLM---requires further development
before the system can support reliable field-level advisory output. This is an honest finding,
and stating it clearly strengthens rather than weakens the manuscript, because it distinguishes
the engineering contribution (which is complete as an integrated prototype) from the diagnostic
reliability contribution (which remains limited by VLM accuracy and parseability) with precision.

\ChapterSubsection{Contributions}

The principal contributions of this project are:

\begin{enumerate}[label=\arabic*.]
\item \textbf{Plant-part detection evidence.} Empirical demonstration that a YOLOv8 nano
detector trained on a curated multi-crop dataset achieves F1 0.73 and mAP@50 0.76 with
documented training dynamics, threshold analysis, per-class evaluation, and quantization
tradeoffs including INT8 deployment at 98 percent baseline performance retention.

\item \textbf{Structured VLM evaluation methodology.} Introduction of parseability as an
explicit evaluation metric alongside classification accuracy for VLM-based diagnosis,
revealing that output-format reliability is a primary bottleneck in structured disease
interpretation. This finding frames the next research question rather than claiming a solved
problem.

\item \textbf{Integrated diagnosis-support architecture.} Implementation and documentation
of an end-to-end workflow from mobile image capture through backend validation, VLM inference,
schema-validated advisory generation, and farmer-facing result delivery, demonstrating how
individually trained model components can be composed into an application-layer system.

\item \textbf{Offline-aware mobile design for agricultural contexts.} Implementation of a
local-first mobile architecture with SQLite persistence, offline scan queuing, cached advisory
fallback, and synchronization infrastructure, aligned with the documented connectivity
constraints of Nepalese rural agriculture.

\item \textbf{Honest limitation reporting.} Systematic identification and documentation of
gaps---VLM prediction reliability, expanding automated test breadth, and the absence of
expert agronomic validation---that define the boundary between what
the current prototype supports and what remains for future work.
\end{enumerate}

\ChapterSubsection{Lessons Learned}

Three lessons from this project extend beyond the specific Krishi Vaidya implementation.

First, \textbf{model training and application integration are qualitatively different problems.}
Training a YOLO detector or fine-tuning a VLM produces a model artifact; integrating that
artifact into a system that validates inputs, handles errors, communicates uncertainty, persists
records, and presents structured results requires engineering effort that is often comparable to
or greater than the modelling effort itself. This observation is consistent with the ML systems
literature \parencite{sculleyMLTechDebt2015,paleyes2022MLSystemsChallenges} and reinforces the
value of projects that attempt the full pipeline rather than stopping at a model checkpoint.

Second, \textbf{the most informative result is often a failure.} The VLM's 67.7 percent
parse-error rate is the most analytically productive finding in this manuscript because it
exposes a specific, reproducible, technically characterizable failure mode. A project that
reported only successful metrics would contribute less to the field than one that documents
exactly where and how the system breaks.

Third, \textbf{designing for offline operation is not an afterthought---it is an architectural
choice that permeates every layer.} Offline support affects data-model design, persistence
strategy, synchronization logic, UI state management, and diagnosis-hook behavior. Treating
offline capability as a feature to be ``added later'' would have required rearchitecting the
mobile application. Embedding it from the initial design stage, consistent with local-first
principles \parencite{kleppmannLocalFirst2019}, avoided that cost.

\ChapterSection{Future Recommendations}

\ChapterSubsection{Immediate priorities}

\begin{enumerate}[label=\arabic*.]
\item \textbf{VLM output reliability.} Investigate constrained decoding, output-format
supervision during training, stricter prompt templates, and higher LoRA rank to reduce the
parse-error rate. This is the single most impactful improvement for system-level diagnostic
quality.

\end{enumerate}

\ChapterSubsection{Near-term improvements}

\begin{enumerate}[label=\arabic*.]
\item \textbf{Backend test breadth.} Extend automated test coverage to include authentication,
crop, task, note, advisory, and diagnosis integration endpoints beyond the current scan-domain
focus.

\item \textbf{Mobile device coverage.} Extend the completed physical-device validation to a wider
set of Android screen sizes and hardware profiles.

\item \textbf{YOLO dataset balance.} Address class imbalance through targeted data collection
for underrepresented classes (rice panicle, brassica leaf, grain cluster) and evaluate the
impact on per-class recall.
\end{enumerate}

\ChapterSubsection{Long-term research directions}

\begin{enumerate}[label=\arabic*.]
\item \textbf{Expert validation.} Engage certified agricultural pathologists and extension
workers to evaluate advisory output quality, appropriateness of treatment recommendations, and
safety of generated pesticide guidance.

\item \textbf{Farmer usability study.} Conduct field-based usability evaluation with Nepalese
farmers to assess interface clarity, language adequacy, diagnostic trust, and workflow fit
within existing agricultural practice.

\item \textbf{Larger VLM exploration.} Evaluate whether a larger base model (7B or 14B
parameters) with LoRA adapters can achieve substantially lower parse-error rates, and whether
the resulting improvement justifies the additional inference cost for a server-side deployment.

\item \textbf{Continuous learning pipeline.} Design an infrastructure for collecting user
feedback, flagging incorrect diagnoses, and retraining model components iteratively---moving
the system toward a supervised-learning loop rather than a static model deployment.
\end{enumerate}
