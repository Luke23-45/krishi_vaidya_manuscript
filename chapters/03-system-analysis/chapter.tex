\chapter{SYSTEM ANALYSIS}

\ChapterSection{System Analysis}

Krishi Vaidya is analyzed as a software system whose purpose is to support image-based crop
disease diagnosis and advisory delivery. The system is not limited to a trained model artifact.
It includes four cooperating subsystems: a YOLO-based plant-part detector, a Qwen-based
vision-language model service, an Express/Mongoose backend API, and a React Native/Expo mobile
application. The analysis therefore treats model inference, backend orchestration, local mobile
storage, offline behavior, and farmer-facing advisory presentation as parts of one workflow.

The primary users are farmers or field-level agricultural users who capture crop images and
review advisory output. The backend and model services act as system actors that validate input,
perform inference, generate structured responses, and store scan history. The project supervisor,
internal examiner, and external examiner are not application users; they evaluate the project
through the report, viva, demonstration, and source-backed evidence.

\ChapterSubsection{Object-Oriented Analysis}

The object-oriented analysis models the application domain as interacting entities rather than
as isolated scripts. The dominant domain objects are User, CropPlot, Scan, Diagnosis, Advisory,
CropTask, CropNote, and local mobile repositories. The backend implementation stores these
entities through Mongoose models and repositories, while the mobile application maintains local
representations through TypeScript types, repositories, SQLite-backed datasources, and feature
view models.
