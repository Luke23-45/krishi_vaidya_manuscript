
\chapter{SYSTEM ANALYSIS}

\ChapterSection{System Analysis}
Chapter 1 introduced four major subsystems that include the YOLO detector, the VLM service, backend API infrastructure, and the mobile application. They form a single continuous workflow. This pipeline deals with model inference and the server, along with local mobile storage and offline handling before finally showcasing the advisory details to the farmer.

Farmers and field workers act as the primary users who take the crop photos to receive advisory feedback. The backend and model services work to validate incoming data, run inference to build a structured response, and store the full scan history for future reference.

\ChapterSubsection{Object-Oriented Analysis}

The architecture for the seven objects; User, CropPlot and Scan, \& Diagnosis, Advisory, CropTask \& CropNote revolves around three base objects and related ones. In backend the data is directly exposed with Mongoose models \& repository objects by the means of these seven domain objects. Mobile clients work a little differently by having mobile repositories with the backed datasource based on SQLite. State remains to be local. With the Typescript objects mobile clients can have those local states for the feature viewmodels exposed on the mobile applications.
